## 当前技术收口缺口：权限 facade 平台归因后的待办

Windows 权限自动入口现已成立：正式命令143通过、15平台不适用跳过、零失败，验证完整 policy 文件而非临时过滤。上次 Windows 直跑的13项错误不再作为13项 Windows 产品缺陷；本轮按源码归属处置如下，不改变生产权限。

| 原失败范围 | 本轮处置与保留的验证 |
| --- | --- |
| POSIX 回收流程、执行计划与 /tmp 删除日志 | 原断言留在真实 POSIX 条件下；Windows 增加 engine/core 两类 owner 的 native delete 回收计划及精确目标断言，均通过 |
| 原工作区写入日志 | 提供明确会话 cwd，采用已建模的 tee 写入，严格检查 writeAuthorizedTarget 子命令日志；普通外部非临时目标要求 ask。Bash 自身允许 scratch 写入属于既有显式策略，不改为虚假外部拒绝 |
| root rm / shred 的拒绝来源与日志 | Windows 验证早期 safety-immune deny，不进入 checker/core，不附执行计划；default/auto/bypass/off 四模式都保留拒绝；POSIX 仍检查原来源/原因，原生未验 |

当前剩余闸：

- 另一类 Unix 主机的真实 policy、chmod/脚本拒绝和适用平台验证未运行。新添坏脚本反向用例使用真实 chmod，仅在Linux/macOS运行，没有 stat mock。
- `test:windows` 旧source-contract曾在不受支持的 PATH Node v22.15.0 下有4失败：fsutil卷探测与3项旧更新安装launcher。新权限闸独立通过，不等于修好这些失败；下一独立回归轮用受支持环境复核并处置，不能全归为环境问题。
- 同版待验源码快照尚未生成，不凭 HEAD 代表全部未提交改动；拿到类Unix机器的系统与交接范围后一次准备。Windows主线可继续；权限/数据隔离和目标平台发行证据不能豁免。
