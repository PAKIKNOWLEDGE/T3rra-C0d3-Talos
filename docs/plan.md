### 定位与允许范围

先读 `app/talos.js` 的 sendAction/sendActionWithResult、连接消息回调、会话打开、发送、停止和审批消费者；`src/service/ws-server.ts` 的动作封包；`talos-service.ts` 的分派；`runtime.ts` 的 EnginePort；`src/adapter/talos-studio.ts` 的 loadSession/sendPrompt/cancel/replyApproval；复用 [动作索引](fulfillment-matrix.md) 与 [接驳证据](adapters/talos-engine.md)。

主改动限于动作结果关联和这四种操作的直接消费者。允许修复 runtime/Studio adapter 的审批 Promise 传播，或提取一个被真实 UI 调用的小型动作结果 helper，以便测试实际生产逻辑。若需核对引擎方法字段，先按 AGENTS 读取 CLI 的 AGENTS/status 再读准确引用源码；CLI 始终只读。不开全局状态重构，不新增操作框架。

已知责任路径：WS catch 当前只回 message，缺 operationId；前端 pendingOperations 按 operationId 找请求；disconnect 当前不清理待决请求。停止和审批忽略 sendAction 的 false 返回。adapter.replyApproval 目前启动异步 RPC 后返回 boolean，runtime 包装立即成功；应让 RPC 失败回到对应动作并保留可恢复的审批事实，不能用卡片消失代替引擎答复。

### 必须成立

1. **关联结果。** 可解析动作的成功/失败返回原 operationId；并发失败只结束自己的请求。不伪造无法解析输入的 ID。断连拒绝并清理待决请求，重连后旧请求不能结算新操作；清理属于客户端等待状态，不夺取引擎状态所有权。
2. **打开与继续。** 打开动作受理不等于历史全部加载；加载失败保持已有回滚/历史错误重试语义。打开后发送沿用当前 sessionId/cwd 与引擎回合事实；离线、忙碌或发送失败不显示完成。保持既有生成中禁止切会话规则，不新建第二套回合状态机。
3. **停止。** 未发出或 RPC 失败给可读错误；受理只表示已请求停止，直到引擎终态才显示已停止。重复点击不重复发送同一待决停止请求；失败后恢复操作入口。
4. **审批。** sessionId/requestId/optionId 来自当前权威请求与引擎选项；RPC 成功后才结算。失败或过期请求不得假成功，失败保留待审批并允许合理重试；同一待决审批不重复发送。跨会话和迟到结果不影响新会话的控件。
5. **显示保留。** 保留既有布局、颜色、字体、表格与思考行为；只调整必要的提示、等待与禁用逻辑。发送层的“受理”与 snapshot 的权威结果分离，不因返回 accepted 就伪造会话或回合完成。

不新增依赖、不改 Studio 协议/权限决策含义、不改 CLI、Markdown、demo、Tauri、队列/分叉/删除等其他操作。触及共享 sendAction 或 WS 逻辑时，只补直接受影响消费者的兼容回归；不能扩展为所有功能重验。

### 用户验收与结束条件

技术复核通过后提供 README 的准确启动入口、同一候选和测试工作区，按已有记录与用户主动操作验收：

1. 打开既有会话，切走再打开或刷新 → 会话归属正确，正文/工具顺序与记录一致；历史失败有清楚错误和重试入口。
2. 在该会话继续一条简短任务 → 流式、结束、思考/工具展开均正常，不出现重复或跨会话污染。
3. 在一个用户主动发起的运行中任务点击停止 → 能区分请求与终态，最终可继续操作；不要求为等待停止编造耗时/危险任务。
4. 如有安全的真实审批记录，选择引擎给出的选项 → 结果明确；没有真实审批场景时由执行者准备注明合成的生产回放并记录真实审批未验，不能让用户到处找触发方法或伪称实测。

执行者负责离线失败场景，用户不承担日志搬运或逐一模拟 RPC 故障。真实请求由用户按已配置 provider 主动发起，代理不自动消耗额度。已确认的 R1/K1/K2 项不重验；仅在对应操作中补 R1 尚未记录的结果。
