# Talos 当前计划

本页只保留目标、待交付范围和唯一下一轮。现状、失败及验收只看 [status](status.md)；执行规则见 [workflow](workflow.md)。原长计划已[归档](archive/2026-10-01/plan-before-scope-reset.md)，不再作为执行入口。

## 目标和范围

做成自己的 Talos CLI：沿用上游引擎，保留已验收的 TUI，第三方 provider 平级，默认数据独立，移除专属账号依赖与不需要的厂商通道，命令只有 talos。许可、NOTICE、权限与沙箱不得为去品牌而删除。Windows 优先；不要求 WSL。GUI 仍暂停，之后恢复 GUI 再做 Tauri 2，不引入 Electron。

这是 fork 收口，不是从零证明一遍整个 agent。继承模块按实际改动影响和适用回归处理；已通过的集成测试保留，不因结尾写有“未验”自动生成新专项。上游发布不保证零缺陷，但也不能仅凭未亲自验证就认定存在阻塞。

## 交付顺序和完成条件

| 交付 | 内容 | 完成条件 |
| --- | --- | --- |
| 1. 修复实际失败 | status 的 F1–F6 按根因成组处理；生产错误修实现，过时断言依据确认的产品契约修测试 | 每组有根因、补丁/处置与受影响检查结果；不得只分类便关闭，不删安全覆盖；不得修活已退役功能 |
| 2. 自己的可安装包 | 正式包身份、版本、talos入口、资源/原生依赖/许可及只读新版提醒；沿用现有打包工程 | F5只处置卷检查和旧安装器契约，不等待候选包。实际候选包安装验证统一在本阶段P2，于临时prefix检查安装、启动、核心使用、升级和卸载。包名/版本在此阶段集中问主人，不猜npm scope，不操作真实账号数据 |
| 3. 发布候选验收 | 同一候选提交与安装包的适用总回归、用户体验、支持平台及说明 | 有具体依据的阻塞全部解决，拟支持平台的现有适用检查/安装证据完备；主人批准才发布，不自行缩平台范围绕过失败 |

以上不是工期或固定轮数承诺。功能范围有限不等于质量可以打折；已知失败不忽略，未知概念不无限展开。包身份、安装和平台支持属于真实发行差异，不能因上游能用就跳过。已建成功能的旧探针不重做。

任务 cli-platform-path-repair/r1。唯一触发为status F4已有三项失败：packages/tui/test/unit/observability.test.ts两项路径分隔符、wsl-attachment-paths.test.ts一项转换失败。只处理这两个文件及复现证明的关联实现，不重建整套平台测试。

先确认Git基点，运行两文件当前基线；对照实际path API、WSL检测和转换调用，分清测试模拟与生产行为。路径期望应检查对应宿主语义，而不是把Windows输出强行改POSIX。若实现缺陷成立，先补adapter源码证据，再修相关路径；保留目录隔离、无多余子进程和失败反馈等强度。

不同时修F5卷/旧安装器、F6lint或发行包，不跑全库，也不复验已关闭F1–F3或无故障继承模块。

## npm 发行与版本提醒

- 开发workspace的private保护保留；修改正式发行manifest，不能把上游包身份直接解锁发布。正式包名/独立版本与检测目标使用同一来源，不能推断npm scope。
- 只读提醒必须随首发交付：发行TUI启动后异步检查一次自己的latest，/update及CLI命令可主动查询，去重；源码未配置构建不自动查，ACP/headless不启动后台检查、不污染协议stdout。
- 稳定语义版本正确比较；超时、404、错误响应说明未确认，不假称已最新。提醒不抢焦点，仅提供准确手动npm安装命令，不下载、执行安装或重启。
- 首发前用假registry验证版本分支及零安装调用，不要求先在npm发布才能写功能；发布后才验证真实包。只有一个版本时不能声称真实升级提醒已验。
- Windows包需实际安装验证；类Unix机器承担其原生适用检查，不安装WSL、不复制Windows node_modules。平台支持声明依真实证据决定；变更支持范围需主人确认。
- 上游合入与发布分开，均不自动执行。**此处可能需要 Astra 把关**：引入自动安装、改变包来源信任、跨仓状态所有权或恢复契约时；普通打包、检查修复和元数据配置由Luna完成。
