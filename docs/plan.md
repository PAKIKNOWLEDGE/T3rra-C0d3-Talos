# Talos Desktop 产品路线与当前任务

## 产品目标

在用户已经满意的 Talos CLI 上，以已确认的 Endfield 视觉交付 Windows 桌面工作台。保留 CLI/TUI 的引擎能力与语义，通过 talos studio 接驳。界面布局以 [design](design.md) 为正本，现状与授权只读 [status](status.md)。

## 路线与停止点

| 阶段 | 交付结果 | 进入下一项的条件 |
| --- | --- | --- |
| R1 对话记录忠实接驳 | 流式正文、完整消息、历史工具顺序可靠，内部 JSON 不污染记录 | 本任务技术复核与用户验收通过 |
| R2 基本操作可靠且可证明 | 打开/继续/停止/审批可确认；辅助检视不挡会话；验证覆盖实际生产路径 | 对应候选通过；仅修明确缺陷或交付欠账 |
| V 发布前界面收口 | 开屏/空态集成、文案复核、用户主导视觉总复核 | 按下方 V 序列逐项通过，保留真实操作验收 |
| R3 Tauri 桌面候选 | 真窗口、系统选目录、明确的引擎定位、启动/退出管理；沿用同一 Studio 和视觉 | [桌面交付边界](tauri-shell.md) 的验收通过 |
| R4 按使用价值完善 | 按实际需求收口队列、分叉、回退、检视等已有接线和后续能力 | 每次独立结果，不把 Studio 方法表当自动待办 |

路线表示依赖，不表示一次性编码授权。R2 具体任务在 R1 结果基础上展开，不重跑上游能力证明。已有高级能力保留，出现明确故障才处理；R3 不等待高级功能全部完善。最终安装与分发不能用开发窗口替代。

## Tauri 前插入的 V 序列

用户已要求插入开屏/空态集成、文案复核和视觉总复核。下面是依赖顺序和分工，不构成并行执行队列；R2-B 用户本次已确认通过，产品基线为 `e091aca`；V0 预览 `8e52c77` 已由用户确认，当前进入 V1 产品接入；未交新候选前保留已通过基线。提案的技术约束见 [开屏与空态提案](proposals/empty-task-layer.md)，视觉正本仍见 design。

| 顺序 | 结果与责任 | 停止与交接 |
| --- | --- | --- |
| V0 方案收敛 | Codex 审查状态映射、焦点和启动边界；用户确认预览的构图/节奏及空态含义 | 本次源码审核已记录，画面未由 Codex 观察；未确认的视觉由用户指示，不靠代理猜 |
| V1 开屏与空态产品接入 | Cursor 按确认方案局部接入 app；Codex 复核生产状态、失败显示与资源；用户看实际集成效果 | R2-B 收口且方案明确后切换唯一任务；交一个冻结候选，不复制预览整页 |
| V2 文案复核与修正 | Codex 从实际可见路径定位文案、给替换清单；Cursor 按清单改；Codex 验语义与残留 | 不另建平行文案库、不借改文案删能力；结果进入下一步视觉验收 |
| V3 用户主导视觉总复核 | 用户给场景和具体修改指示；Codex 汇总为一组有界验收条件；Cursor 实现，Codex 查范围/回归，用户定观感 | 基于同一候选看集成产品；已通过且未影响项不重做，不要求模型自动重设计 |
| R3 Tauri / Windows 交付 | Cursor 做窗口、目录选择、CLI 定位、启动/退出管理和实际构建；Codex 核对宿主边界；用户验真窗口 | 只复验 WebView/缩放/资源/启动带来的差异，不重开整套视觉设计；开发窗口不冒充安装包 |

V1 优先完成，再做 V2、V3：新文案和空态会影响布局，视觉总复核应观察最终集成结果。用户可提前给视觉意见，先记录于 status；不要因此同时修改冻结产品。V3 只修已指出的问题，不能承诺“所有屏幕完美”而无限排查。

### V1 后续任务必须保留的约束

采用应用内一次性开屏，不同时做另一套原生 splash。壳载入即启动既有连接，不用连接成功作为动画开始条件。每窗口载入最多播一次，跳过/reduced-motion/正常结束/异常兜底都必须揭开真实页面；不会因会话切换、snapshot 或重连重播。重复演示按钮只留预览，动画不是加载进度，失败/离线入口始终可达。

空态由已有快照派生：无会话；或会话加载已完成、无显示内容、无 pending 交互且不在运行/停止中时才可邀请开始。历史读取/失败、回合状态、工具、系统错误、审批、问卷及事件页均优先于邀请，不以 timeline 为空遮住它们。新建成功但尚未发送时可以继续空态；输入提交失败保留原内容和恢复入口，不能照搬预览 submit 就切 work 的模拟逻辑。

仅提取预览专属开屏/空层样式与节点，复用当前 composer、字体、token、布局和连接；不搬预览整套 body/grid/色板/mock/sidebar/composer。CSS 状态切换不应反复触发进场。开屏跳过可键盘操作，隐藏装饰不占焦点；结束恢复合理焦点，不定时无条件抢输入。对错误/历史/交互优先级、一次性与退出路径补实际生产 helper 验证；观感交用户。

### V2 文案范围与方法

从 app/index.html、app/talos.js 及实际渲染模块、宿主用户可见错误读取；排除 demo/mock、源码注释、开发日志和引擎原文记录。清单逐条标源码位置、场景、原文、建议及是否需用户定词。统一产品称谓和会话/任务/回合/审批术语；保持受理与完成、空与失败、未连接与请求失败的区别，不把内部协议或工程分层当产品提示。模型正文与外部错误原文不做全局替换；标识符/RPC 不改名。保留用户认可的语言风格，有争议的称谓由用户决定。

### V3 验收范围与发行边界

按用户指示看开屏/跳过、空态/离线/历史失败、短长记录/表格/代码/思考、审批与详情、常用窗口大小/缩放和长文案。不把场景清单自动变成全库重写任务；一次反馈成组，Cursor 修后冻结同一候选。每个独立任务沿用两次交付 fail 后 Codex 接手规则，重试不改任务名清零。

当前是发布前收口规划，尚不是已具备 Windows 发行产物。Tauri、实际构建/启动与分发资产边界仍按 [tauri-shell](tauri-shell.md) 执行；不因开屏/视觉通过宣称发行完成。

### 接入步骤与文件边界

1. 对照已确认预览，只提取 splash 节点、专属样式和空任务层内容。`app/index.html` 增加开屏与独立空层容器，保留现有 stream/record/composer 和所有操作 ID；`app/ui-manifest.json` 登记实际节点/跳过控件。
2. `app/product-motion.css` 接入开屏时间轴和退出；`app/product.css` 仅加作用于开屏/空层的布局样式。浅灰底、黄色斜切面、深色徽标/字标、锁位与揭幕按已选预览保留。不得复制 landing.css 的 :root/body/三栏/composer 全局规则，不改已有颜色、字体、尺寸与阅读密度。
3. 把预览 landing.js 的模拟行为换成生产显示。开屏控制与空态判定可放一个小的 `src/view/startup-surface.ts` 模块供 app 和测试共同调用；普通导出/文件组织由执行者选择，不建第二套快照或回合状态机。
4. 接到现有 `app/talos.js` 的初始化和 renderContent；连接立即开始，开屏期间快照照常更新。只改变主表面显隐和局部装饰，不修改新建、发送、停止、审批、失败输入恢复等 R2-B 已通过逻辑。

源码定位：preview/empty-landing 的 splash 与 empty-layer；app/index.html 的 record/log/composer；app/talos.js 的 connect/render/renderContent/timelineItems；src/core/types.ts 的 ServiceSnapshot；FactStore 的 session.history/history_error 与现有 adapter.requestHistory。只展开这些与直接测试引用，不广泛扫库。

### 必须成立的生产行为

- **开屏一次与可靠退出。** 按已确认约 2.2 秒节奏播放，遮罩退出曲线沿预览；开始不等 Studio 成功，结束不等引擎结果。正常结束/点击或键盘跳过/reduced-motion 走同一个幂等清理入口。刷新等新页面载入可以播放；切会话、快照、重连不得播放。产品没有重播按钮。装饰不绑定加载百分比，不伪造就绪。
- **故障仍可进页面。** 遮罩默认不永久阻挡产品，初始化失败/模块加载失败不留下不可退出的静态开屏；退出有定时兜底。CSS 动画与 JS 无需互相等待才能解除遮挡，消除定时器和监听残留。
- **揭开真实状态。** endSplash 只退出装饰，绝不能 setLayer(empty)、清 stream、重建侧栏、写假用量或重置 session。动画期间加载了既有会话，退出直接看到那个会话。
- **空态与记录优先级。** 事件页保持原样。断连/错误与恢复入口、加载/历史失败、运行/停止、任何实际消息/工具、待审批/问卷等均优先；只有无可显示内容且可安全邀请开始时才显示空层。无会话和已创建空会话使用符合真实状态的提示，输入可用性继续由现有连接/会话条件决定。新建成功没有内容仍可空态；不以点击或提交本身假装已进入记录。
- **真实历史加载。** 当前 session.ready 可能早于 requestHistory 返回，snapshot 只有 historyLoadError，没有独立加载完成字段。不得把“尚未读到”当“已经读完且为空”。优先复用现有显示/操作上下文；若确需字段，允许仅在既有 history 事件链上增加最小显示加载标记（types/FactStore/adapter.requestHistory 及相关测试），遵守 requestId/session 过滤。不得改引擎协议、历史投影/所有权或借此重构状态机；在 status 说明原因。
- **焦点与布局。** 开屏时背景控件不可被键盘误触，跳过立即可用；退出移除/隐藏装饰并解除 inert/监听。只恢复合法焦点，不无条件延时 focus；reduced-motion 不播开屏或待机动画。空层到记录切换不重新播放工作台进场，流式不抢焦点/阅读位置。

### 自验与交付

复用现有 Vite、Markdown、operation-feedback、消息忠实与 UI manifest 检查。新增少量回归须调用真实产品模块，覆盖：开屏多次结束幂等/重连不重播；减少动态跳过；有记录/历史加载/失败/运行/审批/问卷/事件页优先于空态；历史迟到结果不串会话（若新增标记）。有限 Vite 解析/构建证明实际入口可加载，不用测试平行实现、伪 DOM 整页或无头浏览器。

先跑受影响项，再跑一次适用 check:all；登记命令、结果、候选 SHA、改动/旧验收失效范围。代理不启动长期服务、不调用真实模型；浏览器不是本轮代理交付前置，未观察即标未验，用户完成真实画面验收。预览/参考图片不是运行依赖，游戏参考不入产品资源。不新增框架/依赖，不改 demo、CLI、文案全库或 Tauri。

### 用户验收（同一候选）

提供 README 的准确入口、测试工作区与下列 4 步：

1. 启动/刷新 → 已确认开屏出现一次，正常结束进入当时真实页面；立即跳过能到页面，连接照常进行。
2. 新建空会话 → 邀请面显示，保留现有输入区；打开既有会话 → 原记录与工具/表格/思考正确出现。
3. 用户主动继续一条简短请求 → 从空态进入真实记录，流式/结束不重播动画，发送/停止/草稿行为沿用已通过版本。
4. 切会话/重连及系统减少动态场景按实际可用条件观察 → 不重播；加载/离线/错误/审批不被邀请面遮住。缺安全真实故障/审批场景由离线证据负责，用户不用刻意触发。

用户确认后才准备 V2 文案复核清单，随后 V3 用户主导视觉总复核，再 R3 Tauri。保留独立任务两次交付 fail 后 Codex 接手规则；不让 V1 趁机承担全部视觉收尾。
