# Talos Desktop 产品路线与当前任务

## 产品目标

在用户已经满意的 Talos CLI 上，以已确认的 Endfield 视觉交付 Windows 桌面应用。保留 CLI/TUI 的引擎能力与语义，通过 talos studio 接驳。界面布局以 [design](design.md) 为正本，现状与授权只读 [status](status.md)。

## 路线与停止点

| 阶段 | 交付结果 | 进入下一项的条件 |
| --- | --- | --- |
| R1 对话记录忠实接驳 | 流式正文、完整消息、历史工具顺序可靠，内部 JSON 不污染记录 | 本任务技术复核与用户验收通过 |
| R2 基本操作可靠且可证明 | 打开/继续/停止/审批可确认；辅助检视不挡会话；验证覆盖实际生产路径 | 对应候选通过；仅修明确缺陷或交付欠账 |
| V 发布前界面收口 | 开屏/空态集成、文案复核、用户主导视觉总复核 | 按下方 V 序列逐项通过，保留真实操作验收 |
| R3 Tauri 桌面候选 | 真窗口、系统选目录、明确的引擎定位、启动/退出管理；沿用同一 Studio 和视觉 | [桌面交付边界](tauri-shell.md) 的验收通过 |
| R4 按使用价值完善 | 按实际需求收口队列、分叉、回退、检视等已有接线和后续能力 | 每次独立结果，不把 Studio 方法表当自动待办 |

路线表示依赖，不表示一次性编码授权。R2 具体任务在 R1 结果基础上展开，不重跑上游能力证明。已有高级能力保留，出现明确故障才处理；R3 不等待高级功能全部完善。最终安装与分发不能用开发窗口替代。

## Tauri 前插入的 V 序列

用户已要求插入开屏/空态集成、文案复核和视觉总复核。下面是依赖顺序和分工，不构成并行执行队列；R2-B 用户本次已确认通过，产品基线为 `e091aca`；V0 预览 `8e52c77` 已由用户确认，当前进入 V1 产品接入；未交新候选前保留已通过基线。提案的技术约束见 [开屏与空态提案](proposals/empty-task-layer.md)，视觉正本仍见 design。

| 顺序 | 结果与责任 | 停止与交接 |
| --- | --- | --- |
| V0 方案收敛 | Codex 审查状态映射、焦点和启动边界；用户确认预览的构图/节奏及空态含义 | 本次源码审核已记录，画面未由 Codex 观察；未确认的视觉由用户指示，不靠代理猜 |
| V1 开屏与空态产品接入 | Cursor 按确认方案局部接入 app；Codex 复核生产状态、失败显示与资源；用户看实际集成效果 | R2-B 收口且方案明确后切换唯一任务；交一个冻结候选，不复制预览整页 |
| V2 文案复核与修正 | 本次用户指定 Codex 直接查资料并修订，提供原文/新文；用户审核措辞 | 不另建平行文案库、不借改文案删能力；结果进入下一步视觉验收 |
| V3 用户主导视觉总复核 | 用户给场景和具体修改指示；Codex 汇总为一组有界验收条件；Cursor 实现，Codex 查范围/回归，用户定观感 | 基于同一候选看集成产品；已通过且未影响项不重做，不要求模型自动重设计 |
| R3 Tauri / Windows 交付 | Cursor 做窗口、目录选择、CLI 定位、启动/退出管理和实际构建；Codex 核对宿主边界；用户验真窗口 | 只复验 WebView/缩放/资源/启动带来的差异，不重开整套视觉设计；开发窗口不冒充安装包 |

V1 优先完成，再做 V2、V3：新文案和空态会影响布局，视觉总复核应观察最终集成结果。用户可提前给视觉意见，先记录于 status；不要因此同时修改冻结产品。V3 只修已指出的问题，不能承诺“所有屏幕完美”而无限排查。

### V1 后续任务必须保留的约束

采用应用内一次性开屏，不同时做另一套原生 splash。壳载入即启动既有连接，不用连接成功作为动画开始条件。每窗口载入最多播一次，跳过/reduced-motion/正常结束/异常兜底都必须揭开真实页面；不会因会话切换、snapshot 或重连重播。重复演示按钮只留预览，动画不是加载进度，失败/离线入口始终可达。

空态由已有快照派生：无会话；或会话加载已完成、无显示内容、无 pending 交互且不在运行/停止中时才可邀请开始。历史读取/失败、回合状态、工具、系统错误、审批、问卷及事件页均优先于邀请，不以 timeline 为空遮住它们。新建成功但尚未发送时可以继续空态；输入提交失败保留原内容和恢复入口，不能照搬预览 submit 就切 work 的模拟逻辑。

仅提取预览专属开屏/空层样式与节点，复用当前 composer、字体、token、布局和连接；不搬预览整套 body/grid/色板/mock/sidebar/composer。CSS 状态切换不应反复触发进场。开屏跳过可键盘操作，隐藏装饰不占焦点；结束恢复合理焦点，不定时无条件抢输入。对错误/历史/交互优先级、一次性与退出路径补实际生产 helper 验证；观感交用户。

### V2 文案范围与方法

从 app/index.html、app/talos.js 及实际渲染模块、宿主用户可见错误读取；排除 demo/mock、源码注释、开发日志和引擎原文记录。清单逐条标源码位置、场景、原文、建议及是否需用户定词。统一产品称谓和会话/任务/回合/审批术语；保持受理与完成、空与失败、未连接与请求失败的区别，不把内部协议或工程分层当产品提示。模型正文与外部错误原文不做全局替换；标识符/RPC 不改名。保留用户认可的语言风格，有争议的称谓由用户决定。

### V3 验收范围与发行边界

按用户指示看开屏/跳过、空态/离线/历史失败、短长记录/表格/代码/思考、审批与详情、常用窗口大小/缩放和长文案。不把场景清单自动变成全库重写任务；一次反馈成组，Cursor 修后冻结同一候选。每个独立任务沿用两次交付 fail 后 Codex 接手规则，重试不改任务名清零。

当前是发布前收口规划，尚不是已具备 Windows 发行产物。Tauri、实际构建/启动与分发资产边界仍按 [tauri-shell](tauri-shell.md) 执行；不因开屏/视觉通过宣称发行完成。

### 已核对事实与方案

本仓尚无 src-tauri/Cargo 工程。已核对本机存在 cargo/rustc 入口，未确认 MSVC/WebView2 全部构建环境；执行者用有限环境检查补齐，不为缺项更改全局 PATH 或自动安装系统工具。

当前 src/dev.ts 是 Vite + 现有 Node 服务的开发入口，不是交付运行时。src/vite-demo-assets.ts 仅有 configureServer，发布构建不能假定仍从源码 demo 提供字体/样式；当前 app/talos.js 的 WebSocket 连接依赖 location.host / dev 代理。必须处理这两处实际打包差异。

**确定路线：Tauri 2 原生窗口 + 打包前端 + 随包 Node 运行时与编译后的现有桌面服务。** 现有已安装 CLI 是明确前置，不嵌入/升级/复制 CLI 业务；桌面运行不要求源码 checkout、npm、tsx、Vite 长服务或另外手工启动后端。随包 Node 以与已安装 CLI 兼容的已核对版本为准，锁版本/来源/校验并带所需许可记录，不能凭作者电脑 PATH 偶然成功。

Tauri 官方依据：[外部二进制](https://v2.tauri.app/develop/sidecar/)、[Windows 安装包](https://v2.tauri.app/distribute/windows-installer/)、[系统目录对话框](https://v2.tauri.app/plugin/dialog/)。采用随包运行时/资源的正常托管方式；不引入 Electron，不把整个服务迁到 Rust，不创建第二套回合投影。具体 Rust spawn API 与合理构建工具由 Cursor 选择，符合以上合同即可。

### 实施顺序（不要跳过发布路径）

1. **构建与资源。** 建最小 src-tauri、Tauri 2 配置、原生标准窗口和必要权限；复用 app/index.html 与现有入口。Vite 发布构建真正携带基础样式、text-scale、字体、SVG 和开屏资源，不靠 /demo 开发中间件或机器绝对路径。不把游戏参考、preview、真实数据或仓库文档一股脑放进包。构建脚本与 ignore/lock 文件合理调整，生成物不提交。
2. **独立服务入口。** 新增小的生产入口复用 startRuntimeService；编译/打包为随包 Node 可执行的服务资源，不调用 src/dev.ts、不依赖 tsx。Rust 管理自有子进程句柄/启动/退出与有限启动错误；CLI 与服务仍沿已有 talos studio、TalosService、FactStore、WS 路径。
3. **端点与启动。** 后端只绑定本机 loopback，使用自有可用端口（可 port=0）；Tauri 向前端提供本次实际端点，不默认去连接用户已有 5193/5194 服务。桌面启动使用正确工作区 cwd，资源从安装位置读取；首次无工作区或 CLI 缺失时前端照样打开，展示明确恢复入口。浏览器 dev:product 保留原路径，桌面仅做宿主分支。
4. **系统选择目录。** 调用原生 directory picker；选择后沿既有 switch_workspace/启动链进入该目录；取消不改变当前会话/工作区。保留文本路径入口，并把“选择工作区”接到现有区域，不重排界面。可保存最后有效目录；目录消失时给选择入口，不静默退回安装目录。初次未选目录不得偷偷创建任务或使用源码目录。
5. **生命周期。** 正常退出关闭自有 WS/服务/CLI 子进程，失败启动也清理已创建句柄；重新打开只启动自己的一套，不留端口。限定权限/CSP与本地端点访问，不给页面任意 shell 执行能力；若增加宿主访问认证，保持原 ServiceAction 与 Studio 语义不变。不按端口或进程名杀未知服务，不误杀用户 CLI。
6. **实际产物。** 跑 release 构建与 NSIS 打包，交产物的绝对路径、大小、SHA-256、架构与源码候选。关闭执行者自己开的开发服务后启动 release 产物，证明没有 checkout/dev 服务依赖；有限 smoke 不开长期后台服务。安装后产物验证必须实际完成并标范围；若不能安全完成安装，明确标安装未验，不能整体假称安装验收通过。

### 允许范围与保留资产

允许 src-tauri、必要 Tauri/Vite/Node 服务构建脚本和依赖/lock、最小宿主端点/目录接线、资源复制/打包路径、现有 runtime/host 必要退出修复、README 启动/构建命令与聚焦测试。正式 desktop build 命令写 README，不能留成临时 shell 操作。

保留 V1 开屏一次/跳过/焦点、V2 文案与 V3 控件；不新建原生第二开屏、不改颜色字体三栏、不重写消息、审批/停止状态或高阶操作。图标沿 Talos 三六边形标识生成本地构建资源，不做新品牌设计。只有真实 WebView/打包差异才局部修直接回归。

CLI 路径/版本必须取证：复用 installed launcher/entry 定位，桌面不得悄悄回退到 ../Talos-CLI/dist；路径选择或覆盖可作恢复入口。准确说明随包 Node 与本机 CLI 前置，安装包不声称包含 CLI/provider。启动握手失败不假在线、不自动升级用户环境。

### 检查与证据

先跑受影响生产路径离线检查（Vite build/资源、宿主端点与目录取消、CLI 缺失/初始化失败、退出），再跑适用 check:all 与 Rust 检查、一次 Windows release/NSIS 构建。对实际 launcher/资源路径和子进程归属补证，不能只新增字符串覆盖数。真实 CLI 启动/Studio initialize/列会话允许用于本轮有限宿主取证，不自动发送付费请求。

禁止无头浏览器/Playwright/Puppeteer；真实窗口画面由用户最后验收。打包资源包含性、安装产物启动和开发服务独立性属于执行者交付前责任，不把用户当排错员。不碰用户服务；如已有用户服务保留它，桌面用自己的端点验证不依赖它。

构建工具缺失或下载/原生依赖失败，在 status 写准确阻塞与已保存候选，不自动换路线/放宽条件。依赖可以为本任务正常添加，不替换旧框架全库。字体许可等已有分发未核项按 design 原记录保留，本轮为本机安装候选，不宣称公开发行就绪。

### 交付给用户的五步验收

1. 从实际安装入口打开 TALOS → 不用终端/npm 命令即可显示已确认视觉、字体和一次性开屏。
2. 系统选择测试工作区；再试取消选择 → cwd 正确，取消不丢会话/输入。
3. 打开/继续既有会话，用户主动一条短请求并检查停止/安全审批 → 原语义与视觉保留；没安全审批场景就标未验。
4. CLI 缺失/定位失败与启动失败的离线证据由执行者提供，用户只需确认正常恢复入口可理解，不要求搬运日志/制造故障。
5. 退出再打开 → 仍能连接正确工作区，自有进程/端口有退出证据，用户原有 CLI/dev 服务不受影响。

验收前给出安装包与应用入口、版本/候选、CLI前置与限制，不用开发窗口替代。源码提交和产物哈希绑定同一候选；之后仅文档变化须注明。用户通过后才决定后续发行/高级能力，不自动发布。
