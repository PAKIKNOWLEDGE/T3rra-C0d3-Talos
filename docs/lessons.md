# 工程约束与经验

本页是按需参考，不是额外验收队列。当前任务只根据已发生失败、具体改动风险和明确交付要求选择适用项。旧经验来源和事故细节保留在 [重构前快照](archive/2026-10-10-workflow-reset/README.md)。

## 状态与消息

- 引擎事件先保留身份和原始值，再投影显示。以 session / turn / message / part 区分对象；不能按相同正文去重。
- delta、完整 message、历史快照、替换/回退各有不同合并语义。只用一个 append 路径接所有输入会产生重复或丢失。
- partial patch 合并无关字段；明确完整替换的事件按契约替换。禁止把“永远整对象覆盖”或“永远只能合并”当通用规则。
- 进程代次、当前会话选择、运行中回合分别关联；旧响应不能把用户切回旧会话，旧结束事件不能结束新回合。
- 请求受理、业务完成、实际效果分开。取消响应成功不等于已停止，审批卡消失不等于文件操作已完成。
- 加载失败、超时和断开都有恢复入口；辅助检视失败不能覆盖基本会话事实。当前缺字段保持缺失，不伪造数字或计划。

## 分层

宿主管子进程、目录与系统 I/O；适配器解释 Studio 契约；状态层归并事实；视图派生展示；UI 发动作、显示结果。边界要靠实际导入与调用路径核实，不能只看目录名字。

TUI 已有行为可作为源码参照，桌面不能猜协议或另写引擎。也不要为了“共享”绕过 Studio 导入引擎内部实现。先证明哪段规则需要共享，再选最小实现范围。

## UI 与验证

- 生产使用哪份渲染/投影，测试就验证哪份；仅测试一个未被界面调用的 helper 没有对应交付意义。
- fixture 注明契约来源；mock 证明客户端处理，不证明服务端真实可用。完整消息和分片边界都要覆盖与本次故障相关的情况。
- 流式更新不抢焦点、不反复动画、不破坏阅读位置；长文本和工具详情使用已有布局与浮窗。
- 确认操作用壳内对话框；空态给下一动作；控件有可观察结果或错误。manifest、DOM 和截图各自只能证明其范围。
- 不按文件长度盲拆模块；发生责任纠缠、重复实现或修改困难的具体证据时再作局部结构调整。

## 宿主与资产

Windows 路径、UTF-8 跨块、stdout/stderr 与自有子进程生命周期在相关任务中验证；不从“能 spawn”推断通信和退出正确。工作目录始终是用户项目，不能用应用目录代替。

临时 cwd 或 dataDir 不等于系统隔离；不擅改注册表、持久 PATH、真实凭据或用户服务。源码 Git 恢复点不能代替系统设置备份。

视觉正本、素材授权和分发范围见 [design](design.md)。已有上游能力没有新失败或改动风险时，不重复开发专项验证。
