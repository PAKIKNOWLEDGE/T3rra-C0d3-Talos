# Tauri 桌面交付边界

采用 Tauri 2，保留现有视觉和 Studio 协议。此页是路线边界，不是当前可执行任务；何时进入以 [plan](plan.md) 和 [status](status.md) 为准。

## 进入条件

- 对话记录与历史忠实，基本打开/继续/停止/审批路径有相应证据。
- 使用的 CLI 可执行文件、工作区 cwd 与失败提示明确。
- 当前候选已完成技术复核和相应用户验收。

队列、分叉、插件检视等高级能力不要求全部完善后才做窗口。

## 实施时必须决定

Tauri 如何托管现有服务/前端、如何定位已安装 CLI、是否打包 sidecar，应在 R3 展开时依据现有实现选择。现在不写一个未经验证的生产启动方案。

整个应用只保留一条 Studio 接驳和一套消息投影。窗口层负责系统 I/O 与生命周期，不新建第二套回合状态机，不直接导入 CLI 内部模块。先复用用户已满意的 CLI 安装，不自动升级。

## 桌面候选验收

1. 从实际桌面入口启动 → 已确认视觉、资源与字体正确加载；不能依赖代理遗留的开发服务。
2. 系统选择工作区 → 确定后进入正确目录；取消保留当前状态。
3. 打开会话并使用已通过的对话/停止/审批路径 → 行为与同一 Studio 语义一致。
4. CLI 缺失或启动失败 → 可见原因和恢复入口，无假在线。
5. 退出再打开 → 自有子进程和端口生命周期明确，不误杀用户 CLI 或其他服务。

实际 Windows 构建与启动证据由执行者提供，界面由用户验收。开发窗口、debug 程序、可分发安装包分别标注，不互相冒充。公开发行前核对 [资产许可](design.md#资产与分发) 和实际构建产物。
