# 用户、Cursor 与 Codex 的开发工作流

本工作流适用于同一个本地桌面仓库。用户在 Codex 讨论方向与复核，在 Cursor 让执行代理实现。任务和证据写进仓库，跨工具不依赖会话记忆。当前任务见 [status](status.md)，具体合同见 [plan](plan.md)。

## 分工

| 参与者 | 负责 | 交回什么 |
| --- | --- | --- |
| 用户 | 产品取舍、真实使用与视觉验收、决定是否推进 | 对候选的通过范围或失败步骤 |
| Codex 规划与复核者 | 读真实 CLI/桌面代码，确定职责边界和本轮目标；独立看候选 diff 与证据 | 一个可执行任务，或针对候选的具体复核结论 |
| Cursor 执行者 | 按任务读源码、局部调查、实现、自验、保存与记录 | 一个可恢复提交、检查结果、可直接执行的验收步骤 |

能力按任务判断，不按模型名称猜职责。执行者有权选择普通实现方案、修本轮回归、补相关证据；无需逐文件请 Codex 批准。默认由Cursor实现，用户指定或同一任务两次fail后由Codex接手；不凭角色名称阻止已有授权。用户不负责抄源码、汇总测试日志或判断协议字段。

## 一次交付怎么走

1. **准备任务。** Codex 把一个可验收结果写入 plan：触发依据、输入/输出语义、允许范围、禁止范围、完成条件和检查范围。status 指向它。用户说执行或把下方执行提示词发给 Cursor，即授权该任务；文件中的“已就绪”本身不会自动运行。
2. **Cursor 完成。** 核对任务号、Git 基点与工作树，保存必要 WIP；实现和自验在同一轮内完成。任务内普通失败直接修。交回候选提交，在 status 填实施交付，阶段改成“待技术复核”，停止功能修改。
3. **Codex 技术复核。** 用户回到本聊天说“复核当前候选”。Codex 从仓库读基点、候选、diff、实际生产路径和证据；CLI 语义按引用源码核对。结论写 status。阻塞问题返回同一任务；通过后进入“待用户验收”。
4. **用户验收。** 使用候选对应的启动入口，完成任务内 3–5 步操作。只需报步骤和现象，或说明通过范围。执行者负责后续定位。机器已证明的字节、身份和状态语义不让用户逐项手验。
5. **收口与推进。** 记录验收版本和范围。用户只说“通过”就收口并停；说“通过并推进”则 Codex 可准备路线中的下一个有依据的任务，Cursor 仍只执行收到的那一项。

纯文档任务由链接、内容与范围检查验收，不要求运行产品。无可见行为的内部任务，以事先约定的技术完成条件收口。明确批量授权仍有效，但不允许以批量授权跳过其中要求的复核或验收。

## 两次 fail 后接手

用户已确定：同一任务由 Cursor 先执行；交付候选被 Codex 技术复核或用户实际验收明确退回时计一次 fail。首次退回由 Cursor 修同一任务；第二次退回后 Cursor 保存现场并停写，Codex 接手实现与自验，不再安排 Cursor 第三次尝试。接手无需重新申请同一任务的修复授权。

同一候选被技术和用户指出多个问题只计一次，不按问题数量累计；执行过程中的正常自测失败不计交付 fail。status 保存候选、计数、退回原因和下一写入者；新候选不得清空同一任务计数，不能通过重命名任务重置失败。新独立任务从 0 开始。通过的候选不计 fail；失效候选仍留在 Git 中可恢复。

## 当前阶段怎么表达

只在 status 维护阶段：规划中 → 可执行 → 执行中 → 待技术复核 → 待用户验收 → 已完成。

出现具体阻塞时写“受阻”并注明缺的证据、权限或决策；修复后回到原任务。技术复核或用户验收退回后，状态回到“执行中”，保留失败项与失效候选，不另开一串事故任务。

技术通过与产品通过分别记录。用户若先进行了验收，记录其结果；还欠的技术证据仍须补齐。任何相关代码改动都会产生新候选，执行者说明影响哪些已验项目；不把上次通过无条件搬到新版本，也不要求无关项目全部重验。

## 给 Cursor 的执行提示词

复制以下文字即可；权威任务编号以 status 为准：

> 在本仓执行 docs/status.md 指向的唯一“已就绪”任务。先读 AGENTS.md、当前交接卡、docs/plan.md 当前任务和其中指定的证据；首次接手读 docs/workflow.md。核对 Git 基点，保存必要 WIP。完成本任务的实现、相关自验和本地提交，在 status 的实施交付区填写候选与证据，然后停在待技术复核。不要推进后续路线，不改 CLI 或已确认视觉，不以 mock 全绿宣称产品通过。普通任务内问题自行修；遇到契约冲突保存并准确报告。

执行者的第一条回复要能让用户看出它读了任务：任务号、要交付的用户结果、基点、停止点。只复述“我会遵守规则”不算接手完成。

如果收到复核退回，使用下面这句，不必重新发整套计划：

> 继续修复 docs/status.md 中当前任务的复核或验收退回项。保持原合同，完成相关复验并提交新候选，更新 status 后停在待技术复核；不要开启下一任务。

## 给 Codex 的复核提示词

> 复核本仓 docs/status.md 中的当前候选。对照 plan 的任务条件，读取基点到候选的实际 diff、生产消费路径及必要的 CLI 源码；先复用已绑定候选的检查证据，仅在缺证、矛盾或变更影响时补跑。给出阻塞问题或技术通过，写回 status。未实际看画面就不要宣称视觉通过；不要顺手实现下一轮。

复核只围绕本任务、直接回归和保留约束。每条阻塞写：位置、会发生什么、违反哪项条件、如何证明修复；代码风格偏好与无证据的潜在风险不能充当阻塞。发现无关问题只记观察，不扩当前修复范围。

Codex 最少确认以下问题：

- 输入语义来自已核实的 Studio/TUI 代码，而非执行者自己编的桩。
- 生产路径真正使用被检查的实现；没有重复渲染器或旁路状态使测试失去意义。
- 本任务的数据身份、合并、生命周期与失败恢复符合合同。
- diff 没有改变未授权仓库、视觉、协议或产品范围。
- 检查结果、候选提交与用户将启动的代码一致。

## 实施交付与验收证据

不另造“完成报告”文件；更新 status 中的固定区域。至少留下：

| 字段 | 内容 |
| --- | --- |
| 任务与基点 | 任务号/修订、开始前可恢复提交 |
| 候选 | 提交 SHA、相对基点的文件清单/范围、工作树是否干净 |
| 引擎 | 如本轮涉及协议，引用源码 SHA；如运行，另记实际 executable 路径和版本 |
| 改动 | 每项改动解决哪个条件，必要的范围调整 |
| 检查 | 命令、退出码、实际结果；失败、未运行、环境阻止分开写 |
| 行为证据 | 合成契约 fixture 或脱敏回放的来源；真实运行另标，不混为一谈 |
| 用户入口 | README 中准确启动方式、工作区前置、候选、3–5 步动作与预期 |
| 限制 | 本轮没证明的边界；不能据此自动派生新任务 |

真实会话、密钥和原始日志留在忽略目录；只入库合成或去敏 fixture 和必要摘要。截图只能说明拍到的版本与场景，不能替代流数据正确性证据。

## 不让返工蔓延

- 一个任务围绕一个结果或同组根因，不能同时换协议、改视觉、加功能和整理全库。当前任务可以跨必要模块，不机械限制文件数量。
- 每条新增需求必须对应已有失败、改动引起的具体风险或明确交付欠账。“没亲自测过”不构成全库重验理由。
- 先复用现有生产代码和测试。禁止只为增加覆盖数造镜像测试、只给测试使用的实现、空检查脚本。
- 本任务新增失败当轮修；同一根因经过两种有依据的修复仍失败，或输入契约存在冲突时，保存现场交 Codex 缩小问题。不要循环猜测或继续叠补丁。
- 改实现方法、相关 helper 或测试清单，只要仍满足原合同，执行者可记录后继续。要改协议、跨仓写入、改变状态所有权、降低完成条件或重做视觉，先交 Codex 给出具体取舍；产品决定由用户作出。
- 非当前路线的清理、框架迁移、删除遗留目录不能搭车。大文件不是单独立项依据；责任纠缠已经妨碍本轮结果时才拆。

## Git 与候选冻结

先检查待保存清单；脏源码先本地 WIP，干净树复用 HEAD。测试失败不妨碍保存；WIP 不是验收。实施结束保存源码与交付记录。若记录提交号需追加文档提交，候选仍指向被验的产品提交，并注明之后只有文档变化，避免自引用循环。

当前采用同一工作区串行协作，不强制另建 worktree 或引入分支管理系统。Cursor 交回候选后停写，Codex 复核期间不并行修改；用户验收期间也不扩功能。进入下一任务前保留上一份已通过提交。不得为恢复而整库丢弃改动，不默认推送或发布。

.cursor/rules/talos-workflow.mdc 是自动加载入口，执行提示词是显式入口；是否加载应从代理首次回复确认。文档不是权限沙箱，不能保证模型绝不越界。实际约束来自一个写入者、固定候选、可查 diff 和 Codex 独立复核，不能因规则文件存在就省掉这些步骤。

## 检查与运行边界

检查命令集中在 [README](../README.md#检查)。小轮先跑受影响项；交付候选再跑任务约定的适用检查。没有改动、失败或缺证不重复跑。现有 typecheck 和 mock 的限制要如实标注，不能借命令名声称全产品严格类型或真实引擎通过。

长期验收服务由用户外部终端启动；代理不把自己后台进程当交付物，不占用后又随意清理用户服务。真实模型调用只在明确授权用途内，先完成离线工作；付费 smoke 不应成为每次改文档或跑单测的前置。

不使用无头浏览器或 Playwright 等禁止工具。用户已要求由其手动验画面；未经新的明确要求不启动自动界面操作。静态或资源检查不能冒称渲染通过。
